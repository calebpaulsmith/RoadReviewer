The short answer: HPMS or the state?

Two different jobs use two different sources, and they can sit side by side on the same screen.

HPMS tiles decide the verdict

The red / blue / amber status on a row comes from the FHWA HPMS road tiles hosted with this site (2024 submission), plus the 2020 urban-boundary tiles. No state server is contacted for the verdict. The row shows a "Source: FHWA HPMS 2024 tiles" chip (a live verdict shows "Source: MDOT live layer" etc.); the chip links to that source's public page.

State layer decides the verdict only when…

…any one of these is true: the "Live verdicts" box (under Data service URLs) is ticked; the point is outside the six states; the tiles cannot be read (opened from a file, a state's tile file missing, a read error). Then that state's own functional-class layer and the live NTAD urban boundaries are queried per point.

HPMS tiles draw the class lines while you browse

The colored road-class lines that appear from zoom 9 and the urban-boundary outlines are the same tiles. Nothing live is fetched for them.

State layer draws the lines around a selected site and in the PDF

Click a row, step Prev / Next, or export the PDF report and the "Source layers at this site" lines come from the state DOT layer, live, in that state's own published colors, with the urban boundary from the live NTAD service. Same for the class swatch on Find-box road suggestions.

What this means in practice. The verdict and the site overlay can disagree. The tiles are one HPMS year old; the state layer is current. If a collector was reclassified since the 2024 submission, the row may say one thing and the lines around the pin another. Ticking "Live verdicts" makes both use the state layer.

How a verdict is decided, step by step

Every kind of input ends up as one or more points, every point goes down one of two paths, and both paths finish with the same rule.

1. What you typed becomes points

CoordinatesDecimal or DMS, optional site name in front. Used exactly as typed, never rewritten. → one point.
Address (house number + street)Looked up automatically once the line is finished (paste, clicking out of the box, or a typing pause). The Census geocoder returns a point, and the tool snaps it onto the named street in Census TIGER (the raw geocode can land 20 ft from the wrong street). → three points: the snap and 150 ft either way along the street. Disagree → "Review - Class change nearby".
Road name + place("Portage Rd, Portage MI"). The place is looked up in Census TIGER (county → township → city), the road's edges are fetched inside that area, and the 12 longest edges are sampled at their midpoints. → up to 12 points. Different classes along the road → "Review - Mixed classes on road" with a length-by-class summary.

2. Each point picks a path

  • The point is not inside one of the six states.
  • The page was opened as a file, the state's tile file is missing, or a tile read fails.

  • Urban or rural from the NTAD urban-area service, live.
  • Names from the state's own name layer where one exists (MDOT trunklines, INDOT centerlines, WisDOT, ODOT route numbers) plus Census TIGER.
↓

3. The same rule, whichever path

The closest road decides
  • Federal aid — class 1–5 anywhere; class 6 (Minor Collector) when urban.
  • Non-federal aid — class 7 (Local) anywhere; class 6 when rural.
  • Review — no road within the buffer; a named road that the layer gives no class; class 0 (non-certified); a second road within 30 ft that is federal aid; any other federal-aid road nearby; a Minor Collector on the urban boundary.

Amber only ever downgrades blue. Red stays red. The rule tags the road, never the project — it is a direct port of the Excel tool's ComputeVerdict.

↓

4. Where it lands

Row, pin, exportsThe verdict, FHWA class, urban/rural + urban-area name, road name(s) with distances, the state route chip, and a "Source:" chip naming where the class came from (FHWA HPMS tiles or the state DOT's live layer) — on the row, in the pin popup, as the pin color, and in every export (CSV, TSV, GeoJSON, KMZ carry a Data Source column).

The sources, in plain words

HPMS road tiles hosted here

FHWA's Highway Performance Monitoring System, national 2024 submission, harvested once per state and stored as six tile files with the site (41–70 MB each). Every public road with its FHWA class, the state's route id and mileposts, and the HPMS street name. Default source of every verdict and of the class lines you browse.

Shortcomings: one year behind the states; names missing on many rural WI / MN roads; the live service behind it is far too slow to query interactively (2–55 s, errors in metro counties, measured 2026-09-16); county, owner and urban code exist in HPMS but are not in the tiles yet.

Urban-boundary tiles hosted here

The NTAD 2020 Adjusted Urban Areas (549 Region V polygons, 3 MB), from the same USDOT service the live path queries. Decides urban vs rural on the cached path and draws the boundary outlines while browsing.

State DOT functional-class layers live

Each state's own published layer: MDOT (MI), INDOT (IN), WisDOT local + state trunk (WI), MnDOT (MN), IDOT (IL), ODOT TIMS (OH). Current, authoritative, and the only thing the state's official map shows. Used for verdicts only when "Live verdicts" is on or the tiles can't be used; always used for the site overlay, PDF figures and Find-box swatches.

Shortcomings: flaky servers (INDOT 500s, MDOT needs a browser User-Agent, WisDOT moved a layer once); no street names in MN / IL; no county or owner anywhere except Indiana; one point at a time, no name search.

NTAD urban boundaries live

The same 2020 adjusted urban areas, queried per point on the live path and per frame for the site overlay and PDF.

Census TIGER roads live

Every road edge in the country with a parsed street name (base name, type, directions). Street names on rows, the road-name lookup, the address snap, the Find box, and the planned street search. Fast when scoped to a county (0.3 s measured); no class, no county attribute on the edge.

Census geocoder + boundary layers live

The one-line geocoder turns a house address into a point (reached through a sandboxed frame because it sends no CORS header; sent once per finished address line). The state / county / township / place layers back the Find box and the road-name place lookup.

Esri, OpenStreetMap, FEMA display & exports

Esri World Imagery for satellite and PDF basemaps; a Protomaps OpenStreetMap extract for the paper basemap; OpenFreeMap for street-level detail; FEMA's FIRMette print service for the ZIP. None of these touch the verdict.

Planned: the street search box

A street-only search on the map, right side, that requires a state and a county — so the inspector picks a real street from a list instead of typing one for the parser to interpret.
